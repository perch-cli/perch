Perch

Run Claude Code as whichever Claude account you want, without going through the login flow again.

Perch is for one person moving between logins they already hold — their own accounts, on their own machine. It creates no accounts and authenticates nobody; it only chooses between logins you have already made yourself.

Quota ran out. Keep working.

perch switch with nothing after it takes the Account with the most room left, from the Group you said was interchangeable. It asks nothing, because it is what you type mid-task. 

$ perch switch
Cycling within Group `work`.
overflow@example.com has the most room: 60% headroom, which is true of every one of its Quota Windows — 7-day is its fullest, as of 4m ago.
Captured you@example.com's live Credential into its own Profile.
Switched to overflow@example.com.
Utilization   5-hour    12%  (as of 4m ago)
              7-day     40%  (as of 4m ago)

It lands everywhere at once — every terminal, the editor extension, the desktop app. Your memory, settings, plugins and project history do not move: they are yours rather than the Account's.

Or stop being the one who notices

perch watcher run reads how full the Account you are on is, prints what it made of that, and Switches when it runs low. A loop in one terminal, not a daemon — nothing to install, and Ctrl-C is safe wherever it lands. 

$ perch watcher run
Watching you@example.com in Group `work`. Reading how full it is every 2m30s, and Switching within the Group when its fullest Quota Window reaches 80% — to an Account at 70% or under, and never twice inside 15 minutes. Ctrl-C stops.
2026-08-04T12:00:00Z  waiting   you@example.com 40% used, fullest 5-hour; threshold 80% — under it, so nothing was wanted.
2026-08-04T12:02:30Z  switched  you@example.com 86% used, fullest 5-hour; threshold 80% — over it. Switched — overflow@example.com has the most room: 95% headroom, which is true of every one of its Quota Windows — 5-hour is its fullest, as of just now.
^C
Stopped. Nothing was left behind: the watcher holds no lock, writes no file of its own, and the Account you are on is the one it last Switched to.

Every decision is printed, including the ones where nothing happens — which are most of them. Nothing changes underneath you until a Group has been told it may.

And the rest of it

  • perch status — who you are and how full, served from cache so it is cheap enough for a shell prompt.
  • perch add — gain an Account by logging in, without disturbing the one you are using.
  • perch run <target> — launch Claude Code as one Account in one terminal, leaving the active one alone.
  • perch tui — draw all of it, for when the choice wants making by eye.
  • perch holdings export — everything Perch holds, in one encrypted file, readable by the standard age command.

What each of them does, and why it does it that way, is the guide.

Install

Perch is pre-1.0. Every release is real and works, but the command line may still change between them, so no channel hands it to you by default — you ask for it by name. macOS, Linux and Windows. Claude Code has to be installed already, for Perch to have anything to switch between.

macOS and Linux

curl -fsSL https://perch-cli.github.io/perch/install.sh | sh

Windows

irm https://perch-cli.github.io/perch/install.ps1 | iex

Homebrew

brew tap perch-cli/perch
brew install perch

npm

npm install -g perch-cli@dev

The dev tag is deliberate — there is no latest until 1.0.

Anything else

Every release carries checksums and signed build provenance: github.com/perch-cli/perch/releases. The installers verify both. Installing by hand, checking those yourself and building from source are in the install guide.
