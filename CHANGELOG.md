## [Unreleased]

### Added

- every Quota Window in `--json` carries the `group` it meters over, `session` or
  `weekly`. A per-model window is named from a display name Anthropic writes for
  a person and gives no id for, so `window` is a label a script should not key on
  and `group` is the handle beside it

### Fixed

- the profile endpoint is read where it names an Account's email address under
  `email` as well as under `email_address`. It sends the first and Perch looked
  only for the second, so the check that keeps one Account's figures out of
  another's fell back to what the machine holds on every read, on every machine.
  Both spellings are read, because a reply carrying either answers the question
- a per-model Quota Window is named after its model rather than after a codename.
  Anthropic's usage reply describes the same quota twice, and Perch was reading
  the older half, where the weekly Fable window arrives under the key
  `nimbus_quill` and `perch status` printed a row nobody on the machine could
  identify. It now reads the `limits` array, which names the model, so that row
  reads `7-day-fable`. Where a reply carries no `limits` array Perch reads the
  older half as before
- a Marker written before the machine last started stops holding a Profile. On
  macOS and Windows the operating system will not say when a process owned by
  another user began, so a Marker left behind before a reboot — beside a low pid
  the boot handed to a system daemon — could be neither corroborated nor
  dismissed, and refused `relogin`, `remove`, `purge`, `holdings import` and a
  Switch's Capture until somebody deleted the file by hand. A session does not
  outlive a reboot, and the boot is one question no permission stands in front
  of. A Trail start from before a reboot is read the same way
- no figure is filed against an Account nothing says the Credential belongs to.
  Where Anthropic's profile endpoint stops naming an email address, the check
  that keeps one Account's figures out of another's used to remark on the drift
  and pass everything through — for every Account, on every machine, until Perch
  was taught the new shape. It now falls back to what this machine holds: an
  Account's own Profile is one only Perch writes into, and the live Credential is
  vouched for by the Identity beside it or not at all

### Added

- `perch triage` is a new command: it hands what Perch can see of this machine to the Claude Code you already have, and the agent asks what went wrong, investigates, searches the existing issues and drafts the report. Writing all of that out by hand is the last thing anybody wants to do at the moment they need to, and `perch probe` had already gathered everything such a report needs while still requiring somebody to paste it into a form by hand. Perch gathers and hands over, and does nothing else: it neither investigates nor files, so what it owns is the evidence and the redaction on it. The Probe is written twice into `~/.config/perch/triage/run-<millis>/` — `probe.raw.txt` with the real email addresses and paths, which is what the agent investigates from, and `probe.txt` with placeholders, which the playbook says goes into the issue whole and unedited. That redaction is Perch's own rather than an instruction the agent is asked to remember, because an address in a public issue cannot be taken back and a promise from a language model is checked by nobody; both readings come from one gathering, since two passes a second apart could describe different machines. `prompt.md` beside them carries the whole playbook, so with no Claude Code installed the same session is a paste into any other agent. The playbook forbids reading a Credential in any of its three homes, hand-editing the registry, patching Perch's source, preparing a fix PR and running `perch holdings purge` or `perch holdings import` as a fix, and it puts an offer of `perch holdings export` in front of anything that touches the Holdings at all. It also tells the agent to fetch its own newer self from `main` and follow that instead, which is the one document off the network it may take instructions from — everything else it reads is data written by strangers. Perch's source is deliberately not cloned: every expected failure here already carries a sentence naming the belief that stopped holding and the exit code it refuses with, and an agent reading source writes issues that assert a cause, which is worse than one reporting the right evidence. Claude Code is launched bare from `PATH` rather than through a Run, because Reconcile, Carry, a Marker and Target resolution are all machinery a Triage may have been run to investigate; its exit code is Perch's, as a Run's is. Where Claude Code is not installed, or the live Credential will not read, or the active Account is Quarantined, nothing is launched — the session would open at a login prompt instead of a triage — and Perch says which of those it found and names the three files. `--model` passes a model through untouched and nothing is passed by default; `--raw` writes the real names to both copies. Like a Probe it changes nothing: no Adoption, no registry brought forward or saved, and no line in the Trail. What it writes is evidence rather than one of the Holdings, so it carries no version, is never migrated, travels in no Export, and a Purge takes it with the rest of Perch's home; the newest three runs are kept. Reports filed this way arrive on the `Agent-filed report` template and carry the `filed-by-agent` label (ADR a-triage-hands-over-evidence)

- `perch probe` is a new command: everything Perch can see of this machine, gathered for pasting into a bug report. Which Perch and which Claude Code, the Channel that installed it, where Perch's files are, what the Holdings hold, which Account is active, whether a Watcher is arranged and whether any Scope has told it it may act, and which of the six assumptions Perch makes about Claude Code still hold. Above those, a **Findings** section: everything Perch already computes to decide a refusal, said as a sentence with the exit code that refusal carries — a Quarantined Account, a keychain that will not answer, a registry that no command has brought forward, a Service naming a binary that is gone. Nothing is invented for the command, because a rule stated only here is one that goes stale the first time the real one moves. The findings come first and the facts sit under them, so the facts still stand where the judgment is wrong. The Watcher's own log is named and never read — `watch.log` on macOS and Windows, the `journalctl` line on Linux — because its decisions are in the Trail on every platform already. Email addresses, Alias and Group names and your home directory come out as placeholders numbered by the Account's place in the registry, so `<account 3>` is the same Account in every run and two reports a week apart are comparable; `--raw` prints them as they are. It reaches no network, brings no registry forward and adds no line to the Trail, so running it changes nothing about the machine it is describing, and it exits `0` whatever it finds — `--json` carries the same answers as keys, with `null` where the machine gave none (ADR a-trail-is-evidence)

- Perch keeps a **Trail**: two lines per invocation under `~/.config/perch/trail.log`, one when a command starts and one when it ends, holding what was typed and what it exited with. Perch had never written a log line, and the cost was every bug report — a failure arrived as prose from somebody who had already closed the terminal. Two lines rather than one because a single line written at the end is silent about the invocation most worth reporting: a `perch switch` that hangs on a keychain dialog or takes a Ctrl-C leaves nothing at all, where an unpaired start line is `perch probe` saying that a command was started forty minutes ago and never finished. Words after `--` go to Claude Code and are counted rather than written down. A start line carries its pid, so a start with no end can be asked whether the command is still running rather than assumed dead — `perch watcher run` is a loop that leaves one unpaired at all times on every machine with a Service. The Watcher adds a line of its own for the one round that moved something, a Switch — a round turned away recurs every interval for as long as the condition lasts, so those stay in its own log rather than flooding this one. A start left unpaired by a machine going down is read only within the window, since a reboot explains one of those and would otherwise report it for as long as the file held it. The file is moved aside to `trail.log.1` once it passes a megabyte, and the two are read back as one. It is not one of the Holdings: it carries no version, is never migrated, travels in no Export, and a Purge takes it with everything else. Every write of it fails in silence — the one write in Perch that does, because a diary that can refuse `perch switch` is a new way for every command in the product to fail — and it is never written where Perch has no home, so a machine Perch holds nothing on stays one (ADR a-trail-is-evidence)

- `perch watcher status --json` now carries `any_scope_may_act` beside `installed` and `running`. A Service that has been granted nothing holds rather than deciding anything, and that sentence only ever reached a person — so a script asking whether the Watcher was arranged read `installed: true, running: true` on a machine where it would never Switch anything. `true` where some Scope has said the Watcher may act on it *and* has Accounts it may Cycle between, `false` where none has, and `null` where the registry would not load, that being bigger news than this key and said by the command that needs it. Nothing a terminal is shown moves, and no other key or exit code moves

- `watcher-margin-percent` is a Setting a Scope carries, beside `watcher-threshold-percent`, and the registry moves to version 5 for it. The margin is how far under the threshold a candidate has to sit before moving to it is worth doing — what stops two Accounts walking upward together and refuses a destination barely emptier than the Account being left. It was a constant of 10 points on the reasoning that the high end was already reachable by moving the threshold, and that was wrong: the ceiling is the threshold less the margin, so the two moved together, and raising the threshold to 90 to reach a ceiling of 80 also delayed when you were moved off. "Leave at 80, and only arrive under 50" was not reachable by any setting of the one knob, and it is a coherent thing to want. The default is 10, so a Scope that says nothing behaves exactly as before, and a version 4 registry comes forward with the margin unsaid. `0` is refused naming the range: an Account is left at or over the threshold and a candidate set aside above the ceiling, so at a margin of nothing one Account is both full enough to leave and clear enough to arrive at. A margin wider than the threshold is in range and is a Scope that will only move onto an Account with nothing used at all. `perch config get` gains a `watcher-margin-percent` line per Scope, which a script reading that output as the `set` that restores it will see (ADR a-watcher-knob-is-arithmetic)

- `perch list --refresh --json` and `perch status --refresh --json` now carry `refresh.not_kept` beside `refresh.kept`: the sentence saying why figures that were read could not be written to Perch's own record. The human path always printed it, so a log built from the JSON recorded that the figures were lost with no way to learn why. `null` where they were kept

- `perch list <group>` and `perch list ungrouped` now say what that Scope has left to draw on — its **Reserve**: how many of the Accounts a Cycle may choose still have Headroom, the best one's own figure, and the age of the reading it came from. Never one pooled figure, since Accounts sit on different plans and Perch only ever sees percentages. A Scope with nothing left says what is in the way rather than only "none", and one whose Accounts a Cycle may not choose says so under the count rather than inside it. A bare `perch list` says no Reserve — it is one table across every Scope with no heading for the sentence to sit under — while every section of `perch list --json` carries a `reserve` at every breadth, as fields, and `null` where nothing has declared the Scope's Accounts interchangeable or where the Scope holds nobody ([#197](https://github.com/perch-cli/perch/issues/197))

### Changed

- seventeen of the sentences Perch says are shorter, and none of them says less. Each had grown a second half that made the case for the design rather than stating what happened: why two refusals that both end in `perch relogin` cannot be told apart, why `interchangeable` and `watcher-may-act` are two Settings and not one, where Homebrew and npm put a binary, why a Group name may not open with `-`. Every one of those arguments is already made at length in the guide, and a reader who has just been refused wants the rule and the repair rather than the reasoning. What was cut is the reasoning: every fact, every named command and every "nothing was changed" is still there. The four longest fall furthest — the two Switch refusals for a live Credential nothing accounts for from 606 and 581 characters to 441 and 452, the watcher's hold on the ungrouped pool from 585 to 421, and `perch upgrade` on a binary whose Channel is unknown from 501 to 403 — and the three name refusals fall hardest, from 283, 282 and 201 characters to 116, 66 and 130, which brings them into line with the whitespace rule beside them that had always been one sentence. Three sentences the Purge said in two or three wordings each are now said in one place, so a declined Purge, a failed one and a finished one name the Export the same way and all three now say that the next Purge will not write over it. Adoption's two remarks on a machine's first command become one. No exit code moves, no `--json` shape moves, and no refusal changes which failure it is

- a `perch status --refresh` or `perch list --refresh` no longer spends the allowance a running Watcher needs. Anthropic allows roughly 28-30 reads an hour of one Account's usage and a Watcher takes twenty-four of them off the Account you are on, so four to six were left for the person typing — and the failure ran the wrong way round: over-asking throttled the *Watcher*, which then held its round on a figure it could not read and backed off toward twenty minutes, degrading the unattended Switch it was installed for at exactly the moment somebody was watching their quota closely enough to keep asking. While a Watcher holds the watch, a refresh of the Account it is pacing now declines to ask where what the Watcher last read is younger than its 2m30s interval: the cached figure is what a request would have returned, it is shown as always with its age, and the line says which Watcher is keeping it. The command exits `0` — a decline, not a refusal. Only that one Account and only under a Watcher: every other Account is read as before, and with nothing pacing the machine the whole allowance is the reader's. `--json` gains a `just_read` value for `refresh.accounts[].outcome`, beside `observed`, `throttled`, `failed`, `quarantined` and `stopped`. The Watcher's own rounds are untouched, including the burst that reads candidates at a decision (ADR a-watcher-knob-is-arithmetic)

- `perch list` is quicker again, and this time the shape of it changed rather than the constant. Four quadratic terms sat between reading the registry and drawing the table, and each was a fact about the registry being re-derived per row: which Profiles two Accounts share, asked of every Account by `is_a_candidate` and asked of every one; the Alias an Account answers to, which is a scan because the map is keyed by Alias; and two of `validate`'s three collision checks, which run on every `load` and every `save`. All four are now settled in one pass and read by key. Over 400 Accounts a listing falls from 27.9ms to 9.4ms, over 800 from 96.3ms to 17.8ms, and over 1,600 from 360.9ms to 47.8ms; `perch list --json` over 1,600 falls from 846ms to 80ms. Below about a hundred Accounts none of this was ever visible and still is not — at twenty, a listing is process start-up and nothing else. The table, its ordering and every `--json` shape are byte-for-byte what they were

- a `perch watcher run` no longer forks a Node program every round to quote a version it usually never quotes. `Installed` is what a refusal names beside the assumption that failed, and its rule is once per command — the answer cannot change under a process that is already running. A Watcher is not a command: it starts at login and runs until the session ends, so that was about 575 runs of `claude --version` a day. The rule was also wrong for it the other way round, because a Claude Code that auto-updated underneath left every later refusal quoting the version the loop started with. That Claude Code is installed at all is still settled at the top of every round, a `PATH` walk and a stat with no fork; which version it is now waits until something renders it. So a round that refuses nothing asks nothing, and a round that does refuse quotes what is installed at that moment. Every other command keeps the eager read and still refuses up front on a `claude` that will not run. Nothing a Watcher prints moves and no exit code moves (ADR an-assumption-is-probed)

- `perch holdings purge` no longer asks the installed Claude Code its version twice. It probed once at the top, kept the answer, and then the Export it offers probed again for itself — a second `PATH` walk and a second fork of a Node program, a few hundred milliseconds in front of somebody waiting at a prompt. `perch holdings export`, which had none of its own, now does the one probe at its top

- less memory moves through every fallible call in Perch. `PerchError::ProbeRefused` held four fields inline, so it was 96 bytes where no other variant reached 48 — and an enum is as wide as its widest variant, so all 395 `Result` returns in the tree moved 96 bytes and every `?` copied them. Its payload is boxed and the error is 48 bytes. The refusal path pays one allocation on its way to a sentence on standard error, which is the one place in Perch where an allocation cannot be felt. Nothing a refusal says moves

- an HTTP reply no longer exists twice at once. What curl wrote was taken whole and then the body half copied out of it, so peak memory was double the reply on every request — with a ceiling of 8 MiB, that is 16 MiB resident where 8 would do. The status is what curl appends at the end, so the body is that buffer with its tail cut off in place

- a `perch switch`, a `perch run` and an Import each do less work for the same answer. A Switch derived the incoming Credential Store twice, and a derivation is two environment lookups, a slug, a component walk and a SHA-256. Resolving a path rebuilt the path it was handed — `flattened` reconstructed component by component a path carrying no `.` or `..`, which is nearly all of them, and the link walk copied the tail once per level. An Import checked three things about a file a stranger wrote by walking everything already walked. A `perch version` at a terminal built a tree of GitHub's whole release reply to read one string. None of it changes an answer

- a `perch watcher status` reads the installed unit file once rather than once for the binary it names and once for the log

- a `sessions` directory that is there and will not be read no longer makes `perch holdings import` and `perch holdings purge` say a client is running. It is the root-owned one a `sudo claude` leaves, most often, and both commands reached the liveness question through an answer that had already collapsed to yes-or-no — so doubt arrived as "A client is running against the Profile of someone@example.com. Nothing was purged. Quit it and run this again." Nothing had said a client was running; the directory had not been readable, and quitting a client that may not exist fixes nothing. Both now say which directory would not be read and what to do about it — make it readable, or delete it if no client is running — and exit 10 rather than 16, which is the code every other broken assumption about Claude Code already uses. What did not happen is still said either way. Both refusals also name the pid now, as `perch switch` and a Renewal's already do, since a refusal that names a Profile without naming what is holding it leaves the reader to guess which terminal to close. The rule itself is untouched: doubt still resolves towards Live everywhere, and nothing writes into a Profile it cannot answer for. One more thing moves with it, invisible unless a Watcher is running: a Renewal refused because a `sessions` directory would not be read reported the round as having spent nothing, even where it had been reached by Anthropic rejecting the token — so the Back-off, which paces questions nobody is answering, did not pace one that had gone out and come back. It does now. No `--json` shape moves (ADR a-profile-is-live-by-evidence)

- a `perch watcher run` no longer wakes ten times a second for the whole of its life. The wait between rounds napped in 100ms slices and read the interrupt flag between them, because no platform can be relied on to cut a sleeping thread short — `nanosleep` reports how much was left and the standard library goes back round for the rest. That is true; the slice was the wrong answer to it. A round's ordinary wait is 150 seconds, so it was 1,500 wakeups, and the longest is 20 minutes, so 12,000 — on a Service that starts at login and runs until the session ends. Little CPU, and a real cost all the same: it defeats timer coalescing and keeps the core out of its deep idle states, which is what puts a process in `powertop`. The signal handler now wakes the wait rather than the wait polling after it — a self-pipe and one `poll` on Unix, an event and `WaitForSingleObject` on Windows, and a plain sleep where neither is open. Over six seconds of a real run, 59 `clock_nanosleep` calls become one `poll`. Ctrl-C and `systemctl --user stop` stop costing up to a slice with it: a stop signal now ends the wait in 0.1ms rather than up to 100. Nothing the Watcher prints moves and no exit code moves (ADR the-machine-runs-the-watcher)

- a contended Claude Code lock is asked for again in 25ms rather than after a second. `mkdir` is the whole of the lock protocol, so a contender learns the lock is free only by asking again — and Claude Code holds one for a single token refresh, which is tens of milliseconds. A flat second between attempts spent the whole of the first one learning what a 25ms re-try would have. The wait now doubles from 25ms over eight attempts rather than staying at a second over five: 3.175s in all against 4s before Perch gives up, so the same `PerchError::Busy` at about the same wall clock, reached after the contention has had eight chances to clear instead of five. What a Switch does when it cannot have the lock is untouched, and no exit code moves

- a `perch run` no longer rewrites `.claude.json` to write back what it already holds. What crosses into a Profile crosses key by key, and each key was a splice of the whole document: four for `PERSON_KEYS`, then the `projects` entry, then `projects` itself, so up to six full-width buffers allocated, copied and — being wiped on drop — zeroed on the way out, with the result compared against what went in and dropped where they matched. They match on every Run after the first, `PERSON_KEYS` and `PROJECT_KEYS` being settled preferences rather than counters. The splice is now declined where the document already holds what it would write, compared against the value rather than against the document, so nothing is copied at all in that case. On a 13 MB `.claude.json` — the file grows with the person's per-directory history, and it is the largest one Perch touches — the steady-state pass falls from 299ms to 22ms and its peak memory from six copies of the document to none. Two smaller things go with it: a block is re-indented a line at a time rather than a character at a time, and a Carry asks whether a client is already running against the Profile before reading that file rather than after. Nothing a Run does moves

- `perch list` is quicker to say which Accounts share a Profile. The question was asked of every Account and asked it of every Account, and each comparison built three `String`s, so a listing over n Accounts paid 3n² allocations for a question with n answers: 218ms over 800 Accounts, 883ms over 1600. The candidate's slug now goes into one buffer the scan keeps, and slugging an address is one allocation rather than three — 84ms and 324ms. It is still quadratic in comparisons, and below about 25 Accounts none of it was ever visible. The table, its ordering and `perch list --json` are untouched

- [**breaking**] what is installed is asked of a command rather than of a flag: `perch --version` and `perch -V` become `perch version`, and the flag is gone rather than kept beside it. Every other capability Perch has is a command placed by the noun it is about, and which Perch is installed is a fact about Perch and about no Account, which is the row `upgrade` already sits in. It stayed a flag for an implementation reason rather than a design one: clap generates `--version` and answers it by printing and exiting, so the line underneath it had to be written ahead of the parser, and `main` carried a second parser for the bare form alone. Both are gone. `perch --version` now gets clap's `unexpected argument` and exit 2 with nothing pointing at the command, clap's suggestions running from an unknown flag to other flags rather than to a subcommand — there is no second spelling and no deprecation window, the CLI surface being the side that moves. Nothing the command says moves with it: the first line is `perch <version>` exactly, which is what the Homebrew formula's test block asserts on, and the line about a newer Release still appears only at a terminal, is still given two seconds, is still dropped in silence on any failure, and is still switched off by `PERCH_NO_UPGRADE_CHECK`. `perch version` takes no `--json`, `perch upgrade --check --json` already carrying `installed`, `newest`, `channel` and `upgrade_available`; the two stay separate because one is bounded like a question nobody asked and the other like one somebody did. It is also the one command that comes before `migration::bring_forward` rather than after it, so asking what is installed reads and writes nothing on the machine — a migration is a write, and this is the command somebody runs when the machine is already misbehaving. `perch --help` now lists seventeen names rather than sixteen. No exit code moves and no `--json` shape moves (ADR a-command-names-its-noun) ([#313](https://github.com/perch-cli/perch/issues/313))

- [**breaking**] a Group name or an Alias is now held to an allow-list rather than to a list of what it may not contain, and the registry moves to version 4 for it. `validate_name` was a deny-list that grew a clause per harm found: `@` for the address, a leading `-` for `perch run`'s program, whitespace for `perch config get`'s round trip, and the unshowable set twice. Everything else was a name, so `perch group add 🚀`, `perch group add dev★`, `perch alias someone dev.ops` and `perch group add dev/qa` all succeeded. A Target is typed at a shell prompt, often on the second machine months later, so a name of symbols is one somebody has to produce from a keyboard before any command can reach it. The first character is now Unicode's `XID_Start`, `_`, or an ASCII digit, and every later one is `XID_Continue` or `-`. Not an ASCII rule: `café`, `日本`, `дом`, `한국`, `العربية` and `日本-dev` are names, and `2fa` is one because a digit opens a name where `XID_Start` alone would refuse it. The refusal names the character as it draws and as it is spelled, `` `★` (U+2605) ``, a space quoted alone saying nothing. `unshowable_character_in` stays ahead of the allow-list, because XID answers neither `dev\uFE00` nor `dev\u3164` and both draw as `dev`. Left open deliberately: `dеv` with a Cyrillic `е` is still accepted, closing it needing mixed-script detection that costs 38 KB and three crates and that also refuses `日本-dev`. Because the rule refuses names this build itself wrote down, the registry moves and `migration::forward` holds its rename pass to the rules of whichever version the document claims: a version 3 registry comes forward with `dev★` renamed to `dev`, `🚀` to `group` and `-dev` to `dev`, the existing `-N` suffix settling a collision, and the note saying which. One narrowing comes with that: a version 1 registry hand-edited to name a Group `a@b` or `one two` is now named at `load` rather than silently renamed, no version 1 Perch having accepted either, which is already what a hand edit gets under every later version. `perch add` now makes no Group offer at all where an organization's name carries a `.` or a `,`, rather than offering one spelled with it. No exit code moves and no `--json` shape moves (ADR a-target-has-to-be-typeable)

- [**breaking**] a Group name or an Alias carrying a character that draws as nothing is now refused, and the registry moves to version 3 for it. The set behind that rule was picked by hand and had grown holes: `U+FE00` after a letter with no variant form, `U+3164`, `U+FFA0`, `U+034F`, and `U+2065` sitting in the gap between two halves of one range written as two. So `perch group add dev` and `perch group add $'dev\uFE00'` were both accepted, `perch group list` drew two rows both reading `dev`, and Perch's own confirmation line said *Declared the Group `dev`* twice — which one `perch switch dev` finds being decided by nothing, the harm two names differing only in case are already refused for. The set is now Unicode's `Default_Ignorable_Code_Point` taken whole, that property being this question already answered and a subset chosen for it being a second definition that drifts. The cost is that a name carrying a variation selector — `perch group add $'\u2764\uFE0F'` — is refused, naming the character; `$'\u2764'` is not. Because the rule refuses names this build itself accepted and wrote down, `migration::forward` now chains from whichever version a document claims and every step lands on a rename pass, so a registry holding one comes forward with the name repaired and the note saying which. What that pass carries is bounded by history — a name version 2 accepted — so a name no Perch of that version ever wrote is still a hand edit, named at `load` and left. No exit code moves and no `--json` shape moves (ADR nothing-drawn-is-obeyed)

- [**breaking**] `none` and `ungrouped` are one word for one Scope, and now work as one wherever it is named. Both have always been refused as an Alias and as a Group name, and yet each was accepted by only half the commands: `perch list` and `perch config` took `ungrouped` and not `none`, `perch group move` took `none` and not `ungrouped`. The refusal then came from the name validator, which explains the word's meaning on *the other* command and never names the spelling this one takes — so `perch list none` exited 12 with "`none` means no Group at all on `perch group move`" and never mentioned `ungrouped`. `perch list none`, `perch config get none` and `perch group move <target> ungrouped` now succeed where they exited 12, and the two refusals say what the words address rather than which command addresses it. No other exit code moves

- the Watcher's decision log spells a round it lost to another Watcher `replaced` rather than `handed over`. Every other status word is one lowercase token in the eight-cell column the log is skimmed by; two of them pushed the figure three columns right of every other round's, and nothing rendered that line in the suite. A `perch watcher check` that finds nowhere to go no longer ends its line with `Looking again in 15m00s.` — a check exits after printing, so its scheduler's interval decides, which is the rule the held line already followed

- [**breaking**] `--json` now answers a script in every field it has. `perch watcher status --json` carried English where a value belonged: `platform` was `a LaunchAgent`, `a systemd user unit` or `a Scheduled Task that runs at logon`, and `log` was a path on some machines, the command `journalctl --user -u perch-watch -f` on others, and the sentence `nowhere — nothing names a log file` where there was none — so nothing could be branched on without matching prose. `platform` is now the arrangement as a word — `launchagent`, `systemd` or `scheduled-task` — and names the arrangement rather than the operating system, because that is what the answer turns on. `log` is now the path or `null`, and the sentence a person reads moves beside it as `log_said`, which is the `reason`/`said` pair a Quarantine already emits. The two camelCase keys Perch had — `binaryExists` here and `upgradeAvailable` in `perch upgrade --check --json` — become `binary_exists` and `upgrade_available`, which is how every other key in every other command is spelled. No exit code moves, and nothing either command prints to a terminal changes

- [**breaking**] every command is now placed by the noun it is about, and the Account is the one left unsaid. The four that broke that rule move onto two nouns: `perch export`, `perch import` and `perch purge` become `perch holdings export|import|purge`, and `perch watch` becomes `perch watcher run` — taking `perch service install|uninstall|status` with it as `perch watcher install|uninstall|status`, because a Service is an arrangement of the Watcher rather than a noun of its own. `perch --help` now lists sixteen names rather than nineteen. `perch watch --once` becomes `perch watcher check`, a verb rather than a flag because it changes both the meaning of the exit code and the lifetime of the command; the exit codes themselves are untouched, and no other flag is affected. `Holdings` — everything Perch holds on this machine — is a glossary term ([#164](https://github.com/perch-cli/perch/issues/164))
- `perch switch` now says what it did rather than why it did it. A Cycle prints where it landed, what that Account was chosen on and the Group it stayed inside, and then the Utilization the Switch bought — three lines where there were seven. Gone are the ranking's defense (`60% headroom, which is true of every one of its Quota Windows — 7-day is its fullest`), the staleness paragraph under the figures, the `Cycling within Group `work`.` opening now folded into the landing line, and the Capture line: a Capture happens before every Switch without exception (ADR 0006), and what happens every time is the guide's to establish once. The five Captures that are *not* the ordinary one still speak, every figure still carries its age (ADR 0015), and the three refusals — everything exhausted, already on the best, nothing declared interchangeable — keep their explanations and their exit codes, because a refusal is the one moment somebody cannot predict what happened ([#223](https://github.com/perch-cli/perch/issues/223))
- the Watcher's decision log now says what a round did and explains itself only where a round refused. `waiting` and `switched` become data — `2026-08-04T12:02:30Z  switched  86% used, fullest 5-hour → overflow@example.com`, down from about forty words — because the threshold is declared once in the opening line and does not change within a run, and `under it` / `over it` is what the status word already means. `cooling`, `nowhere`, `held` and `refused` keep their sentences whole (ADR 0036): nothing happened, and the reader cannot see why. The Account leaves the round line, since the opening names the one being watched and every `switched` line names the one it moved to; the timestamp stays a full RFC 3339 instant, because a `perch watcher check` under cron is read cold days later. `Stopped.` loses the three reassurances that were true of every stop without exception ([#224](https://github.com/perch-cli/perch/issues/224))
- `perch list` now says each invariant fact once beneath the table.
